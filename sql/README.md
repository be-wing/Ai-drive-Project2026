# SQLファイルの実行記録

このフォルダーには、授業で使用するSQLを保存します。
SQLファイルをGitHubへpushしても、Neonのデータベースでは自動実行されません。
実行前にNeon SQL Editorで対象のブランチとデータベースを確認し、手動で実行します。

接続文字列、パスワード、APIキーはここに記載しません。

## 第2回 必須課題：接続先の確認

| 項目 | 記録 |
| --- | --- |
| SQLファイル | `000_check_connection.sql` |
| 実行場所 | Neon SQL Editor |
| Neonブランチ | （実際に選択したブランチ名） |
| データベース | （実際に選択したデータベース名） |
| 実行日 | （実際の日付） |
| 結果 | `connection_test` が `1`。接続先DBと実行ユーザーを確認した |

`000_check_connection.sql` は読み取り専用です。接続先、実行ユーザー、SQLを実行できることを確認します。テーブルやデータは変更しません。

Expressの `/api/db-check` でも接続を確認します。このAPIはSQL Editorでファイルを実行する操作とは別です。

| 環境 | `/api/db-check` の結果 |
| --- | --- |

| Vercel Preview | （成功／未確認／失敗） |
| Vercel Production | （成功／未確認／失敗） |

商品一覧の演習を実施していない場合は、「未実施」と記載します。

| Neonブランチ | （実際に選択したブランチ名。未実施なら「未実施」） |
| データベース | （実際に選択したデータベース名。未実施なら「未実施」） |
| 実行日 | （実際の日付。未実施なら「未実施」） |
| 結果 | （商品3件を確認／未実施／確認できなかった） |

このファイルを実行した場合は、`products` テーブルとサンプル商品を作成します。PreviewとProductionには授業で同じNeon接続先を設定しているため、商品データは共有されます。SQLファイルのpushやPull Requestのマージだけでは、商品データは登録されません。

## 実行順

1. `000_check_connection.sql`：接続先を確認する。
2. `010_setup_sample_products.sql`：商品一覧の演習を行う場合だけ実行する。

後からSQLを追加したときも、ファイル名だけで実行済みと判断せず、このREADMEに実際の実行先・順序・結果を記録します。
